## Hard constraints

These are not preferences.

1. **`DESIGN.md` governs every visual decision.** Black and white only —
   no hue anywhere, including "just for errors". Poppins. Tabular figures on
   money and dates. **Status is carried in words, never colour.** If the
   interface loses meaning in greyscale, it is wrong.
2. **Devnet only.** No mainnet transaction has ever been signed by this
   project and none may be. Anything simulated must be labelled as simulated
   on the screen it appears on.
3. **Never write "generated by AI" anywhere** — not in commits, not in the
   README, not in code comments.
4. **Never commit** `program/scripts/state.json` (demo keypairs),
   `web/server/applications.json` (KYB data), `web/server/demo-collateral.json`,
   or `web/.env`. All are gitignored. Check `git diff --cached` before pushing.
5. **Do not touch `~/Projects/Float`.** Different repo, the real product. This
   hackathon entry is deliberately separate.

## The shape of the frontend

```
main.tsx          Privy > Wallet > App.  Order matters (see Traps).
App.tsx           Signed out -> SiteShell + Landing.  Signed in -> AppShell.
privy.tsx         Privy provider, the Wallet Standard bridge, session context.
wallet.tsx        Connect button, wallet menu, PrivyAutoConnect.

components/
  SiteShell.tsx   Logged-out chrome: top bar, footer. No sidebar.
  AppShell.tsx    Logged-in chrome: sidebar, header, mobile nav.
  ui-kit.tsx      Headline, Stats, Rows, StatusWord, KeyLink.
  ui/             shadcn. Import cn from "@/lib/utils", never from "cn".

screens/
  Landing.tsx     The front door. 191 words. Keep it short.
  Journey.tsx     The app: stage machine, draw, repay.
  Profile.tsx     Identity, credit, collateral, advance history, KYB.
  Compare.tsx     Two real businesses, read from chain.
  About.tsx       How it works and what it is not.
  steps/          Apply (KYB), Choose (which rail), Pledge (pool), Escrow (tokens).

lib/
  chain.ts        PDAs, decoders, one batched RPC per screen.
  actions.ts      Every transaction a borrower can sign.
  pricing.ts      The margin ladder. Mirrors pricing.rs. Tested against it.
  history.ts      Past advances, rebuilt from program events.
  errors.ts       Program errors -> sentences.
  useConnected.ts The borrower's stage, derived from chain, never stored.
  useNetwork.ts   Landing page figures.
```

**The stage is derived, never stored.** `useConnected` reads the chain and
decides: `unverified | unsecured | ready | drawn`. There is no local flag that
can drift. Do not add one.

## Traps

Every one of these cost hours. They will not announce themselves.

**1. `tsc --noEmit` is not the build.** The production tsconfig has
`noUnusedLocals`. `npx tsc --noEmit` passes, `npm run build` fails. Run the
build.

**2. A green build has shipped a blank page twice.** Both times everything
passed and the page was white. **Open it in a browser. Every time.** Check the
console, not just the pixels.

**3. Vite's dep cache goes stale after `npm install`.** Symptom: production
build fine, dev server blank, console says "Could not resolve X".
Fix: `rm -rf node_modules/.vite` and restart.

**4. `tailwind-merge` deletes colours.** It does not know Float's type scale
(`text-micro`, `text-meta`, …) and reads them as *colours*, so
`cn("bg-primary text-primary-foreground", "text-micro")` silently drops the
text colour. That shipped a black badge with black text on it. The scale is
registered in `lib/utils.ts` — if you add a size token, add it there too, and
**import `cn` from `@/lib/utils`**, never from the `cn` package.

**5. React effects and the wallet adapter.** `wallets` from `useWallet()` and
`wallets` from Privy's hook are both **new array references on every render**.
Depending on them directly is an infinite loop. This already caused ~270 failed
connections a second on a page that looked completely normal. Key effects off a
derived string.

**6. Privy mounts outside `WalletProvider`.** The adapter reads the Wallet
Standard registry when it mounts, so Privy must register first. Do not reorder
`main.tsx`.

**7. Devnet rate-limits everything.** Any new `getTransaction` loop needs
backoff and a cache — see `history.ts`. Batching makes it worse, not better.

### Counting errors, not looking for them

The infinite-loop bug was invisible on screen. This is how it was caught:

```js
window.__n = 0; const o = console.error; console.error = (...a) => { window.__n++; o(...a); };
setTimeout(() => console.log("errors:", window.__n), 6000);
```

A healthy page scores **0**. Anything above single digits is a loop. Compare
against `git stash` to attribute it.

## Open questions

**1. The Privy round trip is unverified.** Sign-in → embedded wallet →
`useWallet()` → signing has never been completed by a human, because it needs
an email OTP. Everything up to it is verified: the modal talks to the real app
ID, and registering a Standard Wallet does reach the adapter.

If it fails, the recovery state says which half broke:
- *"no Solana wallet came back"* → Solana embedded wallets are not enabled in
  the Privy dashboard. Not a code fix.
- *"Finish connecting"* → the wallet exists, the adapter did not take it.
  That is `PrivyAutoConnect` in `wallet.tsx`.

**2. No human has signed a real draw through the UI.** The program paths are
proven by scripts; the browser → wallet → program round trip is not.
**This is the highest-value thing left to check.**

**3. The app ID is not committed.** `.gitignore` excludes `web/.env`, so a
judge cloning the repo gets no Privy and falls back to wallet-only, which
works. `web/.env.example` documents it. Privy app IDs are public client
identifiers, so committing it is safe if you want judges to have email sign-in.

## If you are picking frontend work

Roughly in order of value:

1. **Walk the whole flow yourself with a real wallet**, all the way to a signed
   draw. Everything below matters less than knowing this works.
2. **The Apply form** (`steps/Apply.tsx`) is the least-revised screen. It is
   the first thing a judge touches after connecting.
3. **Mobile below 375px** has been checked for overflow but not designed.
4. **`Compare.tsx`** shows Acme with `$0.00` collected across all six cycles,
   so its history does not demonstrate collection-at-source. Either seed it or
   say so on the screen.
5. **Loading states** are `Skeleton` almost everywhere. The profile history
   takes ~30 seconds cold and only says "Reading your history off the chain".

Do not add a colour to fix a hierarchy problem. Use type, weight and space —
that is what the scale in `index.css` is for.
